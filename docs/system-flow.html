System Architecture

System Flows

1 Onboarding
  1. Venue Owner → API Server → DB
    POST /auth/register with role: "venue" — atomic transaction creates venue record + user account, returns JWT pair
  2. Device → API Server → Device
    POST /api/v1/devices/register — server issues a non-expiring RS256 device JWT; stored permanently on the device
  3. Advertiser → API Server → DB
    POST /auth/register with role: "advertiser" — creates advertiser record + user account, returns 15-min access token + 7-day refresh token
2 Campaign Setup
  1. Admin → API Server → DB
    POST /api/v1/slots — defines a sellable time window on a device (e.g. Mon–Fri 11am–2pm, $150/week)
  2. Advertiser → API Server → S3 / R2 → Advertiser
    POST /api/v1/assets/upload (multipart, 100 MB max, advertiser JWT) — stores creative in Cloudflare R2 at creatives/{uuid}.{ext}; returns CDN URL
  3. Advertiser → API Server → DB
    POST /api/v1/bookings with the CDN URL — availability check → booking insert → slot status set to booked; no double-booking possible
3 Ad Delivery Loop repeats every 60 s
  1. Device → API Server
    POST /api/v1/devices/:id/heartbeat — updates last_seen and status: online; rate-limited per device in Redis
  2. API Server → DB / Redis → Device
    Scheduler checks Redis cache first (TTL 60 s); on miss, queries Postgres for active bookings matching current day/time; returns ordered playlist
  3. Device → HD Display
    Plays each ad in sequence — images fade in/out, video plays to completion; green status dot confirms active playback
  4. Device → API Server → DB
    POST /api/v1/devices/:id/impression — records {booking_id, device_id, played_at} for billing and analytics; rate-limited (30 req/min/device)
